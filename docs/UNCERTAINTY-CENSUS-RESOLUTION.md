# Uncertainty census - resolution record

This document is the closing record for the uncertainty census run over the
`dual-log-engine` governance layer. Every census item carries a stated resolution;
nothing was dropped. The full per-item review (raw census) lives in
`UNCERTAINTY-CENSUS.md`; this file is the audited tally plus a per-item disposition.

## What each bucket means

- **already-fixed** (25): The flagged issue was already resolved in the code before this census closed; no further change needed.
- **actionable** (101): A real, cheap, standards-grounded improvement worth making; addressed by the resolution swarm.
- **documented-limit** (97): A genuine boundary of the design (heuristic/best-effort/threat-model scope) that is acknowledged in the docs rather than fixed.
- **intentional** (123): Behaviour is deliberate and correct as designed; the census note is an explanation, not a defect.
- **non-issue** (9): On inspection the concern does not hold (false alarm / based on a misread); no change warranted.

Every item below resolves into exactly one bucket. The `actionable` items were
implemented by a clustered fix swarm (see the per-area working files); the other
four buckets are dispositions that, by design, change no code.
